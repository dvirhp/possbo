# Server Architecture — Possbo Backend

## Entry Point

`src/index.js` — Express app setup, HTTPS, middleware chain, route registration, scheduler start.

```
Request Flow:
  → Helmet → CORS → JSON (1MB) → URL Parser → Cookie Parser
  → Rate Limiter → Static Files → JWT User Loader → Routes → Error Handler
```

## Authentication Flow

```
Register:
  POST /api/auth/register
  → Turnstile CAPTCHA validation
  → hash password (bcrypt, 12 rounds)
  → create User → send verification code email
  → return { accessToken } + set refreshToken cookie

Verify Email:
  POST /api/auth/verify-email
  → verify code → mark email as verified

Login:
  POST /api/auth/login
  → verify password → check email verified
  → return { accessToken } + set refreshToken cookie

OAuth:
  POST /api/oauth/:provider
  → validate provider token/code
  → find or create User + ConnectedAccount
  → return { accessToken } + set refreshToken cookie

Token Refresh:
  POST /api/auth/refresh
  → read refreshToken from httpOnly cookie
  → verify → generate new accessToken
  → return { accessToken }

Protected Routes:
  Authorization: Bearer <accessToken>
  → JWT user loader middleware → sets req.user
  → requireAuth middleware → 401 if no req.user
```

### Token Config

| Token   | Lifetime   | Storage         | Secret               |
| ------- | ---------- | --------------- | -------------------- |
| Access  | 15 minutes | Client memory   | `JWT_SECRET`         |
| Refresh | 7 days     | httpOnly cookie | `JWT_REFRESH_SECRET` |

## Facebook Automation (`utils/facebook-automation.js`)

All Facebook interaction uses **Playwright** with stored browser cookies (no Graph API for posting).

### Key Functions:

| Function                                          | Purpose                                                                 |
| ------------------------------------------------- | ----------------------------------------------------------------------- |
| `bootstrapFacebookSession(userId)`                | Opens visible browser → user logs in manually → saves cookies encrypted |
| `loadUserStorageState(userId)`                    | Decrypts stored cookies → returns Playwright storage state              |
| `saveUserStorageState(userId, state)`             | Encrypts cookies → saves to `user.facebookStorageState`                 |
| `scrapeMyGroups(userId)`                          | Headless browser → navigates to /groups → extracts group list           |
| `publishToGroup(groupUrl, text, imagePath, opts)` | Headless → navigates to group → creates post → returns postUrl          |
| `getStorageState(userId)`                         | Returns raw decrypted state for validation                              |

### Session Lifecycle:

1. User clicks "Connect Facebook" → `bootstrapFacebookSession` opens visible browser
2. User logs in manually → cookies saved encrypted with AES-256-GCM
3. Every 7.5 hours → `session-keepalive.js` validates cookies still work
4. If expired → nullifies `facebookStorageState` + creates `SESSION_EXPIRED` notification

## Instagram Integration (`routes/instagram.js`)

Instagram publishing uses the **Instagram Graph API** (unlike Facebook which uses Playwright).

### Flow:

1. User connects Instagram via OAuth (`/api/instagram/auth-url` → `/api/instagram/connect`)
2. Access token stored in `ConnectedAccount` table
3. Publishing: upload media to public URL → create container → publish via Graph API
4. Supports: Feed posts, Stories, Reels

## Background Jobs (`jobs/`)

Started via `startScheduler()` called from `index.js` after server listen.

| Job                        | Interval   | Purpose                                             |
| -------------------------- | ---------- | --------------------------------------------------- |
| `processPublicationJobs()` | 60 seconds | Find PENDING jobs, lock, publish via Playwright     |
| `generateScheduledJobs()`  | 5 minutes  | Create PublicationJob from active PostGroupSchedule |
| `runSessionKeepAlive()`    | 7.5 hours  | Validate all users' Facebook sessions               |
| `refreshGroupMetadata()`   | Daily      | Sync member counts, privacy type from Facebook      |
| `collectMetrics()`         | Periodic   | Scrape engagement metrics from published posts      |

### Publication Job Lifecycle:

```
PENDING → lock (optimistic) → RUNNING → publish via Playwright
  ├─ Success → SUCCESS + PublicationHistory + PublicationMetric
  └─ Failure → retry with exponential backoff (10/20/40 min)
      └─ Max 3 attempts → FAILED + Notification to user
```

### Optimistic Locking:

```sql
UPDATE publication_jobs
SET status='RUNNING', locked_at=NOW(), locked_by=<workerId>
WHERE id=<jobId> AND status='PENDING' AND locked_at IS NULL
```

## Database Schema (Key Models — 26 total)

### Core:

- **User** — email, passwordHash, encrypted FB creds, facebookStorageState, avatar, gender, phone
- **ConnectedAccount** — OAuth integrations (provider, providerUserId, accessToken)
- **Group** — name, url, externalId, memberCount, privacy
- **UserGroup** — user-to-group relationship (join table)
- **Post** — content, status (DRAFT/ACTIVE/PAUSED/ARCHIVED), userId, media[]

### Publishing Pipeline:

- **PostMedia** — images/videos attached to posts
- **PostGroup** — links Post to Group (many-to-many with userId)
- **PostGroupSchedule** — frequency config (ONCE/DAILY/WEEKLY/MONTHLY), nextRunAt
- **PublicationJob** — queue entry (PENDING/RUNNING/SUCCESS/FAILED/CANCELLED)
- **PublicationHistory** — record of each publish attempt with timestamps
- **PublicationMetric** — engagement metrics (likes, comments, shares, reach, impressions)

### Content:

- **PostTemplate** — saved post templates for reuse (with usage counter)
- **PostVersion** — post history / versioning

### User Management:

- **UserSession** — session tokens
- **PasswordResetToken** — password reset flow
- **EmailVerificationToken** — email verification flow
- **Notification** — userId, type, title, message, isRead

### Analytics:

- **DailyStats** — aggregated daily publication metrics
- **DailyExposure** — daily reach/impression tracking
- **GroupSyncHistory** — group sync operation tracking

### Billing:

- **Subscription** — user subscription state
- **Plan** — subscription tiers
- **UsageLimit** — rate limiting per tier
- **Payment** — transaction history

### Audit:

- **AuditLog** — action tracking

## Encryption

All sensitive data encrypted at rest using AES-256-GCM:

- Facebook App ID / App Secret (per-user)
- Facebook Storage State (cookies)

Format: `salt:iv:authTag:ciphertext` (hex-encoded, colon-separated)  
Key derivation: PBKDF2 (SHA-512, 100k iterations) from `ENCRYPTION_KEY` env var.

## Error Handling

```javascript
// Route-level: asyncHandler wraps async route handlers
router.get("/path", asyncHandler(async (req, res) => { ... }))

// Auth-level: requireAuth middleware for protected routes
router.get("/path", requireAuth, asyncHandler(async (req, res) => { ... }))

// App-level: global error middleware in index.js
app.use((err, req, res, next) => {
  log.error("Unhandled error", err);
  res.status(err.status || 500).json({ error: err.message || "Internal server error" });
})
```

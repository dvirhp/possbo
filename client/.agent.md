# Client Architecture — Possbo Frontend

## Tech Stack

- **React 18.2** — functional components, hooks only
- **Vite 5** — dev server (:3000), build tool
- **React Router 6** — client-side routing (22 routes)
- **Axios** — HTTP client with JWT interceptors
- **Recharts** — charts and analytics
- **Lucide React** — icon library
- **Hebrew UI** — RTL direction, all text in Hebrew

## Authentication Flow

```
┌─────────────────────────────────────────────────────────────┐
│ http.js — Axios Instance                                     │
│                                                              │
│ • Stores accessToken in memory (NOT localStorage — XSS-safe)│
│ • Attaches Authorization: Bearer <token> to all requests    │
│ • On 401 response → auto-calls /api/auth/refresh            │
│   → If refresh succeeds: retries original request           │
│   → If refresh fails: clears token, redirects to /login     │
│ • Request queue: concurrent 401s wait for single refresh    │
└─────────────────────────────────────────────────────────────┘
```

### Login Flow:

1. User submits email + password (+ Turnstile CAPTCHA on register)
2. `authAPI.login()` → server returns `{ accessToken }` + sets httpOnly cookie
3. `setAccessToken(token)` stores in memory variable
4. Navigate to `/dashboard`

### OAuth Flow:

1. User clicks OAuth button (Google, Facebook, GitHub, LinkedIn, Apple)
2. Redirect to provider → callback to `/oauth/:provider/callback`
3. `OAuthCallback` extracts code → sends to backend → receives tokens
4. Navigate to `/dashboard`

### Page Load (protected pages):

1. `AuthLayout` wrapper → calls `authAPI.refresh()`
2. If succeeds → token restored, load user data via DataProvider
3. If fails → navigate to `/login`

## Key Patterns

### State Management

- **DataProvider** — global context: user info, groups, notifications, loading states
- **ThemeProvider** — light/dark toggle, persisted in localStorage
- **NavigationGuard** — protects routes, handles unsaved changes warning

### Background Publishing

- `CreatePost` dispatches custom events: `possbo-publish-start`, `possbo-publish-done`
- `App.jsx` listens → shows global banner notification with progress
- Multi-group: client fires `Promise.all()` for parallel publish requests

### Responsive Design

- Mobile: `BottomNav` + `PullToRefresh` gesture
- Desktop: `Sidebar` navigation
- `AccessibilityWidget`: font size, high contrast, reduced motion

### Code Splitting

- Protected pages use `React.lazy()` + `Suspense`
- `TopLoader` shows NProgress bar during route transitions

## Components

### `GenericList`

Reusable list with:

- Search/filter input
- Items rendered with name, optional image
- Click navigates to `basePath/:id` with item data in state
- Supports external URL links

### `LocationAutocomplete`

- Debounced input → queries OpenStreetMap Nominatim API
- Dropdown with location suggestions
- Returns selected location string

## Styling Conventions

- **One CSS file per page/component** — no CSS modules, no CSS-in-JS
- **RTL by default** — `direction: rtl` in App.css
- **Design system colors**:
  - Primary gradient: `#667eea → #764ba2`
  - Error: `#dc2626` on `#fef2f2`
  - Success: `#155724` on `#d4edda`
- **Responsive** — media queries at 768px and 600px breakpoints
- **Card-based UI** — `border-radius: 14px`, `box-shadow` for elevation
